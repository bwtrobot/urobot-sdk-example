# example 同步 SDK 4.1.0 方案

## 目标与依据

对齐 s1-maincenter 的 `sdk-robot-model-4-1` 变更，将新增机型详情查询接入 example，并验证真实 SDK 的调用链路。现有 example 使用 SDK 3.3.0，机器人列表映射及前端类型缺少动态机型编码。

## 推荐方案

1. 将后端 core、services、ws 依赖统一升级至 4.1.0，检查现有接口编译兼容性。
2. 新增只读 BFF 接口 `GET /robot/model?modelCode=…`，校验非空编码，调用 `RobotClient#getRobotModel`，显式映射详情及嵌套文件，保留历史字段为空的语义。
3. 补齐机器人列表的动态机型字段与前端类型，新增类型完整的机型查询 API，沿用现有调试来源标记机制。
4. 本次范围以 SDK 新增只读查询契约为准。远程模型在三维场景中的加载需先核对文件格式及资源引用契约；不凭机型名称推断资源地址。

## 可选方案与取舍

- 仅升级依赖：改动少，但不能演示和验证新增接口能力。
- 完整查询链路（推荐）：覆盖 SDK 新能力与 example 前后端调用，范围与上游变更一致。
- 同时重做动态三维模型加载：覆盖面更大，但需要额外明确资源格式、下载地址生命周期和加载失败处理。

## 验证

- 后端集成测试通过本地 HTTP 桩服务连接真实 SDK，从 BFF 入口验证开放接口路径、查询参数编码、详情与文件字段、空白编码及上游失败。
- 前端测试验证查询参数、动态编码、可空历史字段和错误来源，避免将 mock 降级误判为真实集成成功。
- 执行后端测试、前端全量测试和生产构建，检查已有导航、讲解和实时连接相关回归。
- 如有可用测试环境和凭据，再执行只读真实环境查询；报告中分别记录本地集成与环境联调结果。
