uRobot OpenSDK Java 是面向 uRobot 具身智能中枢 Open API 的 Java 8+ 客户端。SDK 封装 AccessKey/SecretKey 签名、Token 获取和刷新、HTTP 连接池、错误处理、重试策略和分页遍历，业务代码只需要构建请求对象并调用对应服务客户端。

当前版本覆盖 /api/open/v1 下的机器人、地图、拓扑路径、导航路径、讲解、动作等接口。SDK 不依赖 Spring，可在普通 Java、Spring Boot、批处理任务和集成平台中使用。

1. SDK 概述

SDK 由核心能力和服务客户端组成：

  • 核心能力：认证、Token 管理、HTTP 传输、JSON 映射、异常和分页基础模型。

  • 服务客户端：机器人、地图、路径、讲解和动作相关接口封装。

核心调用流程为：构建 URobotClient，选择领域客户端，构建 Request，调用接口并读取 Response。SDK 会在请求前自动获取 Token，并在 Token 过期或服务返回 401 时刷新后重试一次。

2. 环境要求

  • JDK 8 或更高版本。

  • Maven 3.8 或更高版本。

  • 可访问 uRobot 具身智能中枢 Open API 服务端地址。

  • 已开通的 AccessKey 和 SecretKey。

SDK 使用 Apache HttpClient 5、Jackson 和 SLF4J，不需要 Spring 容器。

3. 安装

在应用中引入 services 依赖即可获得完整客户端能力：

<dependency>
    <groupId>io.github.bwtrobot</groupId>
    <artifactId>urobot-opensdk-services</artifactId>
    <version>4.1.0</version>
</dependency>

如仅需认证、HTTP 或基础模型，可单独引入 core 依赖：

<dependency>
    <groupId>io.github.bwtrobot</groupId>
    <artifactId>urobot-opensdk-core</artifactId>
    <version>4.1.0</version>
</dependency>

4. 凭证配置

AccessKey 和 SecretKey 用于生成签名并换取 JWT Token。推荐在生产环境通过环境变量注入：

export UROBOT_ACCESS_KEY=your-access-key
export UROBOT_SECRET_KEY=your-secret-key

Java 代码中使用 EnvironmentCredentialsProvider：

URobotClient client = URobotClient.builder()
    .endpoint("https://urobot.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .build();

本地调试或命令行工具也可以使用静态凭证：

StaticCredentialsProvider.create(
    AccessKeyCredentials.of("your-access-key", "your-secret-key"));

5. 第一个请求

try (URobotClient client = URobotClient.builder()
        .endpoint("https://urobot.example.com")
        .credentialsProvider(StaticCredentialsProvider.create(
            AccessKeyCredentials.of("your-access-key", "your-secret-key")))
        .build()) {

    ListRobotsResponse response = client.robot().listRobots(
        ListRobotsRequest.builder()
            .pageNum(1)
            .pageSize(20)
            .build());

    for (RobotItem robot : response.data()) {
        System.out.println(robot.name());
    }
}

URobotClient 实现 AutoCloseable，建议按应用生命周期复用，并在应用退出时关闭。

6. Hello Robot

机器人领域入口为 client.robot()，常见操作包括查询列表、查询运行态、下发指令和查询任务结果。

GetRobotRuntimeResponse runtime = client.robot().getRobotRuntime(
    GetRobotRuntimeRequest.builder()
        .robotId("robot-sn")
        .build());

SendCommandResponse command = client.robot().sendCommand(
    SendCommandRequest.builder()
        .robotId("robot-sn")
        .type(1)
        .messagesType("robot_patrol")
        .params(Collections.singletonMap("target", "A101"))
        .callbackUrl("https://callback.example.com/openapi/task")
        .build());

type 和 messagesType 的取值范围以服务端 Open API 文档为准；params 的结构由具体指令类型决定，建议与对应指令定义保持一致。

7. 创建客户端

URobotClient 是线程安全的入口对象，会复用 HTTP 连接池、Token 管理器和子客户端。

URobotClient client = URobotClient.builder()
    .endpoint("https://urobot.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .build();

endpoint 填写 Open API 服务地址，不需要包含 /api/open/v1。SDK 会自动拼接 Open API 前缀。

8. CredentialsProvider

SDK 内置两种凭证提供者：

  • StaticCredentialsProvider：代码中显式传入固定 AccessKey 和 SecretKey。

  • EnvironmentCredentialsProvider：从 UROBOT_ACCESS_KEY 和 UROBOT_SECRET_KEY 读取。

凭证对象 AccessKeyCredentials 不可变，会在创建时校验空值。

9. HTTP 配置

HttpConfiguration 支持连接超时、读超时、最大连接数和代理配置。

HttpConfiguration httpConfiguration = HttpConfiguration.builder()
    .connectTimeout(Duration.ofSeconds(3))
    .socketTimeout(Duration.ofSeconds(10))
    .maxConnections(100)
    .defaultMaxPerRoute(20)
    .build();

URobotClient client = URobotClient.builder()
    .endpoint("https://urobot.example.com")
    .credentialsProvider(EnvironmentCredentialsProvider.create())
    .httpConfiguration(httpConfiguration)
    .build();

生产环境建议按应用并发量配置连接池上限，避免每次请求创建新客户端。

10. 重试策略

默认 maxRetries 为 0，不对 429、5xx 或 IOException 做业务重试。Token 过期导致的 401 会触发 Token 刷新并立即重试一次。

RetryPolicy retryPolicy = RetryPolicy.builder()
    .maxRetries(3)
    .build();

启用重试后，SDK 会对 429 使用 Retry-After 或默认等待时间，对 5xx 和网络异常使用指数退避。

11. Request 和 Response

每个接口都有独立的 Request 和 Response 类型。Request 使用 Builder 创建，构建后不可变；Response 由 Jackson 反序列化，未知字段会被忽略。

ListMapsRequest request = ListMapsRequest.builder()
    .pageNum(1)
    .pageSize(50)
    .search("展厅")
    .build();

ListMapsResponse response = client.map().listMaps(request);

接口返回业务失败时不会返回空 Response，而是抛出 ServiceException。

12. 分页

分页 Request 默认 pageNum=1、pageSize=20。分页接口同时提供手动分页和自动分页迭代器。

ListRobotsResponse page = client.robot().listRobots(
    ListRobotsRequest.builder().pageNum(1).pageSize(20).build());
for (RobotItem robot : client.robot()
        .listRobotsPaginator(ListRobotsRequest.builder().pageSize(50).build())
        .items()) {
    System.out.println(robot.id());
}

自动分页为惰性加载，迭代到下一页时才发起请求。

12.1. 动态机型查询

机器人列表可使用可选的 modelCode 字符串筛选动态机型，例如 ListRobotsRequest.builder().modelCode("custom_robot").build()。GET 查询发送 modelCode（camelCase）；响应通过 RobotItem.modelCode() 读取 model_code。与旧 terminalType 同时提供时以 modelCode 为准；旧 terminalType 方法保留兼容。动态机型的 terminal_type_value 可能为空；旧服务端缺少 model_code 时 modelCode() 返回空值。无编码的历史记录由服务端按旧枚举映射兼容。

13. 错误处理

SDK 异常基类为 URobotException：

  • ClientException：客户端侧问题，例如配置错误、网络异常、序列化失败。

  • ServiceException：Open API 返回业务失败，包含 errorCode、errorMessage 和 requestId。

try {
    client.robot().listRobots(ListRobotsRequest.builder().build());
} catch (ServiceException e) {
    log.warn("Open API failed, code={}, requestId={}",
        e.errorCode(), e.requestId());
} catch (ClientException e) {
    log.error("SDK client failed", e);
}

14. RobotClient

RobotClient 覆盖机器人查询、任务控制和单点导航接口：

  • listRobots / listRobotsPaginator：分页查询机器人。

  • getRobotRuntime：查询机器人运行数据。

  • sendCommand：下发任务指令。

  • getTaskResult：查询任务结果。

  • setCallback：设置数据订阅回调。

  • navigation：按导航点名称或位姿下发单点导航并等待最终结果。

单点导航请求支持 pointName（非空时优先按名称处理）和 toward（forward / backward，默认 forward）：

NavigationResponse response = client.robot().navigation(NavigationRequest.builder()
    .robotId("robot-sn")
    .pointName("F1")
    .positionX(2.2522).positionY(-0.881949538099388).positionZ(-1.3875)
    .orientationX(-0.014707664919881869).orientationY(0.7203878073631774)
    .orientationZ(0.6934150971808892).orientationW(-0.0007711009636985258)
    .navVoiceControl(false).lookAt(true).toward("forward")
    .build());

查询任务结果示例：

GetTaskResultResponse result = client.robot().getTaskResult(
    GetTaskResultRequest.builder()
        .robotId("robot-sn")
        .taskIds(Collections.singletonList("task-id"))
        .build());

14.1. 机型详情查询

从机器人列表的 RobotItem.modelCode() 获取编码后，可查询已启用且未删除的机型主数据及资源引用。使用 Open API 凭证调用 GET /api/open/v1/robot-model，必填查询参数为 modelCode（camelCase）。

GetRobotModelResponse response = client.robot().getRobotModel(
    GetRobotModelRequest.builder().modelCode("Go2").build());
RobotModel model = response.model();
if (model.urdf() != null) {
    String downloadUrl = model.urdf().url();
}

以上类型位于 io.github.bwtrobot.opensdk.services.robot.model。RobotModel 包含标识、设备类型、中英文名称、机型编码、三个文件 key、URDF 主路径、虚拟动作支持、自动充电模式、状态、描述、时间以及 urdf() / cardPoster() / ratioPoster() 文件对象。完整字段以 RobotModelResponse 契约为准，时间使用 ISO 8601 字符串。文件对象提供 fileId()、fileName()、contentType()、url()、disposition()；未配置资源时可为空。

terminalType() / terminalTypeValue() 保留历史描述及枚举值，动态机型可能为空；业务应优先使用 modelCode()。缺失或空白编码在 SDK 构造请求时被拒绝；机型不可用或文件引用异常沿用服务端业务错误，由 SDK 抛出既有异常。该功能自 4.1.0 提供，服务端也须部署对应开放路由。

15. WebSocket 实时数据通道

SDK 提供 WebSocket 实时数据通道，允许开发者订阅机器人 Topic 数据（速度、点云、相机帧、关节状态等），并接收 OpenAPI 任务结果的实时推送。

15.1. 前置条件

使用 WS 实时通道需要额外引入 urobot-opensdk-ws 模块：

<dependency>
    <groupId>io.github.bwtrobot</groupId>
    <artifactId>urobot-opensdk-ws</artifactId>
    <version>${urobot-opensdk.version}</version>
</dependency>

15.2. 启用 WS 配置

构建 URobotClient 时通过 wsConfiguration() 启用 WS 能力：

URobotClient client = URobotClient.builder()
    .endpoint("https://your-server.com")
    .credentialsProvider(StaticCredentialsProvider.create("accessKey", "secretKey"))
    .wsConfiguration(WsConfiguration.builder()
        .maxReconnectAttempts(5)        // 最大重连次数，默认 10
        .reconnectInterval(Duration.ofSeconds(10)) // 重连间隔，默认 5 秒
        .maxBackoff(Duration.ofSeconds(60))         // 最大退避间隔，默认 60 秒
        .robotOfflineMaxBackoff(Duration.ofMinutes(5)) // 机器人离线最大退避间隔，默认 5 分钟
        .reconnectForever(false)                    // 是否无限重连，默认 false
        .connectionStableThreshold(Duration.ofSeconds(60)) // 稳定窗口，默认 60 秒
        .maxBinaryMessageSize(10 * 1024 * 1024)     // 二进制接收上限，默认 10MB
        .heartbeatInterval(Duration.ofSeconds(30))  // 心跳间隔，默认 30 秒
        .connectTimeout(Duration.ofSeconds(10))     // 连接超时，默认 10 秒
        .build())
    .build();

未配置 wsConfiguration 时，调用 robot().realtime(robotId) 将抛出 ClientException。

15.3. 建立连接

// 获取 RobotRealtimeClient（同一 robotId 返回同一实例）
RobotRealtimeClient realtime = client.robot().realtime("robot-uuid");

// 注册事件回调
realtime.onConnected(() -> System.out.println("已连接"));
realtime.onDisconnected(reason -> System.out.println("断开: " + reason));
realtime.onKicked(() -> System.out.println("被其他客户端挤占"));

// 同步阻塞连接（内部获取 WsToken → 建立 WS → 启动心跳）
realtime.connect();

connect() 是同步阻塞方法，成功返回后 WS 连接已建立。连接失败或超时会抛出 ClientException。

连接成功后，SDK 会先重放本地已注册的 Topic 订阅，再触发 onConnected 回调，首次连接与重连语义一致。

15.4. 订阅 Topic

// 使用 Topics 常量避免拼写错误
realtime.onTopic(Topics.CMD_VEL_ROBOT, data -> {
    System.out.println("速度数据: " + data.jsonData());
});

realtime.onTopic(Topics.CURRENT_POINTCLOUD, data -> {
    byte[] pointcloud = data.binaryData();
    // 处理点云二进制数据
});

realtime.onTopic(Topics.ROBOT_UPLOAD_INFO, data -> {
    System.out.println("机器人状态: " + data.jsonData());
});

// 也可以订阅自定义 Topic
realtime.onTopic("/custom/topic", data -> {
    // 处理自定义 Topic 数据
});

15.4.1. TopicData

每次推送通过 TopicData 传递，同时承载文本和二进制数据：

  • topic() — Topic 名称

  • jsonData() — JSON 文本数据（可能为 null）

  • binaryData() — 二进制数据（可能为 null）

  • hasJson() — jsonData 是否非空

  • hasBinary() — binaryData 是否非空

15.4.2. robot_upload_info 快照

订阅 robot_upload_info 后，SDK 自动维护最新快照。通过 getRobotInfo() 随时获取：

String info = realtime.getRobotInfo(); // 最近一次推送的 JSON，未收到时返回 null

15.4.3. 取消订阅

realtime.unsubscribe(Topics.CMD_VEL_ROBOT);

15.5. 任务结果推送

注册 onTaskResult 回调接收 OpenAPI 任务的实时状态推送：

realtime.onTaskResult(data -> {
    System.out.println("任务结果: " + data.jsonData());
});

// sendCommand 后 taskId 自动注册到 TaskCache
SendCommandResponse resp = client.robot().sendCommand(request);

15.5.1. TaskCache 本地缓存

TaskCache 提供 LRU + TTL 缓存，通过 WS 推送自动更新：

// 查询缓存中的任务结果
String result = realtime.taskCache().get(taskId);   // 缓存的 JSON，未命中返回 null
String status = realtime.taskCache().getStatus(taskId); // PENDING/EXECUTING/FINISHED/ERROR/TERMINATED

TaskCache 为最佳努力缓存，以 HTTP getTaskResult() 为权威。

15.6. 连接管理

15.6.1. 重连策略

网络异常、心跳超时、服务端关闭码 4401 / 4402，或重新获取 WsToken 时返回机器人离线错误 20002 时，SDK 自动在后台重连。重连流程：按指数退避 + 随机抖动等待 → 重新获取 WsToken → 重连 WS → 自动重订阅所有 Topic。

机器人离线归因为 ROBOT_OFFLINE，退避上限使用 robotOfflineMaxBackoff；其它网络类断开使用 maxBackoff。

如果一次网络断开已触发 onDisconnected(NETWORK_ERROR)，但后续后台重连在获取 WsToken 时发现服务端返回机器人离线错误 20002，SDK 会追加触发一次 onDisconnected(ROBOT_OFFLINE)，用于把当前断因升级为机器人离线。按断开次数统计的调用方需要注意这个行为；按连接状态消费时应以最新一次 reason 为准。

连接保持 CONNECTED 达到 connectionStableThreshold 后，SDK 才会清空重连预算；若在稳定窗内再次断开，预算会继续累加，避免 flapping 连接无限翻滚。

重连次数达到 maxReconnectAttempts 时停止，触发 onDisconnected(EXHAUSTED)；设置 reconnectForever(true) 时会持续重试，不主动进入 CLOSED。

15.6.2. 被挤占

服务端限制每个机器人只允许一个 OpenControl 连接。新连接建立时旧连接被挤占，收到 CLOSE_CONNECT 后触发 onKicked()，不触发自动重连。

关闭码 4403 的行为与被挤占一致：SDK 不重连，并回调 onKicked() / onDisconnected(KICKED)。

15.6.3. 回调线程

onTopic / onTaskResult / onConnected / onDisconnected / onKicked 都在 SDK 内部的单线程回调执行器上顺序执行，避免阻塞 WS IO 线程。

15.6.4. 关闭连接

realtime.close();  // 关闭 WS、停止心跳、清理订阅
// 关闭后调用任何方法将抛出 IllegalStateException

// URobotClient.close() 也会级联关闭所有 RobotRealtimeClient
client.close();

15.7. 动态机型编码

GET /api/open/v1/nav/{robotId}/open-connect 的连接响应新增可选 modelCode，通过 WsTokenResponse.modelCode() 读取。该接口使用camelCase；历史 terminalType 可能为空，请优先使用动态机型编码。

16. MapClient

地图领域入口为 client.map()，并提供二级子客户端：

  • client.map()：地图列表、版本、充电桩、导航点导出。

  • client.map().topoPath()：拓扑路径查询。

  • client.map().navPath()：导航路径查询。

  • client.map().narration()：讲解稿和讲解流程。

  • client.map().action()：动作列表和动作详情。

ListMapsResponse maps = client.map().listMaps(
    ListMapsRequest.builder().pageSize(20).build());

GetNavPathAllPathByEditionResponse paths = client.map().navPath()
    .getAllPathByEdition(GetNavPathAllPathByEditionRequest.builder()
        .editionId("edition-id")
        .build());

16.1. 讲解流程的多节点行为

讲解流程节点可以配置多个自身行为。请使用 selfScripts()、selfScriptNames() 和 selfScriptValids() 读取完整列表；单值访问器仅用于兼容旧代码。stopover() 表示执行完该节点后是否停留，旧服务端未返回此字段时返回 true。

ListNarrationProcessesResponse response = client.map().narration().listProcesses(
    ListNarrationProcessesRequest.builder()
        .editionId("edition-id")
        .build());

for (NarrationProcess process : response.data()) {
    for (NarrationProcessNode node : process.nodes()) {
        List<String> selfScripts = node.selfScripts();
        List<String> selfScriptNames = node.selfScriptNames();
        List<Boolean> selfScriptValids = node.selfScriptValids();
        boolean stopover = node.stopover();
    }
}

16.2. 展开读取讲解运行时片段

不设置 segmentMode 时，服务端保持原有的折叠形态。需要逐个跟踪节点行为时，在查询或控制请求的 builder 中设置 SegmentMode.EXPANDED。

GetNarrationRuntimeResponse runtimeResponse = client.robot().getNarrationRuntime(
    GetNarrationRuntimeRequest.builder()
        .robotId("robot-id")
        .segmentMode(SegmentMode.EXPANDED)
        .build());

ControlNarrationResponse controlResponse = client.robot().controlNarration(
    ControlNarrationRequest.builder()
        .robotId("robot-id")
        .editionId("edition-id")
        .processId("process-id")
        .command("start")
        .segmentMode(SegmentMode.EXPANDED)
        .build());

node-pick / self-trigger 插播时可设置 mode("manual")，表示停止原讲解流程并独立插播；不设置或设置为 auto 时，服务端按自动插播处理，插播完成后恢复原流程。

EXPANDED 形态下，SELF 片段的 selfIndex() 是该节点 selfScripts() 的从 0 开始下标。非 SELF 片段、折叠形态或旧服务端响应可能返回 null，使用前必须同时检查 null 和列表范围。以下代码承接本节上面的 response 和 runtimeResponse：

Map<String, NarrationProcess> processesById = new HashMap<>();
for (NarrationProcess process : response.data()) {
    processesById.putIfAbsent(process.id(), process);
}

for (NarrationRuntime runtime : runtimeResponse.runtimes()) {
    NarrationProcess process = processesById.get(runtime.processId());
    if (process == null) {
        continue;
    }

    // 只在当前运行时所属的讲解流程内建立节点映射，避免不同流程复用导航点时互相覆盖。
    Map<String, NarrationProcessNode> nodesByRuntimeNodeId = new HashMap<>();
    for (NarrationProcessNode node : process.nodes()) {
        String runtimeNodeId = node.navNodeId();
        if (runtimeNodeId == null || runtimeNodeId.trim().isEmpty()) {
            runtimeNodeId = node.id();
        }
        if (runtimeNodeId != null) {
            nodesByRuntimeNodeId.putIfAbsent(runtimeNodeId, node);
        }
    }

    for (NarrationSegment segment : runtime.segments()) {
        if (!"self".equals(segment.segmentType())) {
            continue;
        }
        NarrationProcessNode node = nodesByRuntimeNodeId.get(segment.nodeId());
        Integer selfIndex = segment.selfIndex();
        if (node != null && selfIndex != null
                && selfIndex >= 0 && selfIndex < node.selfScripts().size()) {
            String selfScriptId = node.selfScripts().get(selfIndex);
        }
    }
}

17. 性能建议

  • 复用 URobotClient，不要为每次请求创建新客户端。

  • 对批量查询使用 SDK 提供的批量接口，例如地图版本批量查询。

  • 分页遍历时按应用处理能力设置 pageSize，避免单页过大导致服务和客户端内存压力。

  • 对幂等查询接口可启用 maxRetries，对可能触发业务副作用的操作谨慎启用重试。

  • 服务退出时调用 client.close() 释放连接池。

18. 日志

SDK 使用 SLF4J API，不绑定具体日志实现。应用可使用 Logback、Log4j2 或其他 SLF4J 兼容实现。

18.1. traceId

SDK 会在需要记录内部日志时生成本地 traceId，格式为 sdk- 加 12 位随机十六进制字符。调用方也可以在发起业务调用前设置外部 traceId：

TraceContext.runWithTrace("order-20260624-001", () -> {
    robotClient.sendCommand(request);
});

请求 Builder 也支持传入 traceId。当 Builder traceId 与当前线程上下文同时存在时，业务客户端优先使用 Builder 上的值。

18.2. 推荐字段

SDK 内部日志使用 key=value 字段，便于 grep、Loki 或 ELK 检索。常见字段如下：

  • traceId：SDK 本地链路 ID。

  • event：日志事件名，如 http_success、send_command、task_cache_updated。

  • requestId：服务端 HTTP 响应 ID。

  • robotId：机器人 ID。

  • taskId：机器人任务 ID。

  • method、path、statusCode、durationMs：HTTP 请求上下文。

  • topic：WebSocket Topic。

  • disconnectReason：WebSocket 断开原因，如 NETWORK_ERROR、HEARTBEAT_TIMEOUT、KICKED、EXHAUSTED。

  • attempt、delayMs、errorType：重试和异常上下文。

18.3. 日志级别

  • INFO：低频关键生命周期事件，如 WS 连接成功、重连成功、被挤占、重连耗尽、sendCommand 返回 taskId。

  • DEBUG：诊断事件，如 HTTP 请求开始和成功、Token 刷新、Topic 订阅、TaskCache 注册和更新。

  • WARN：可恢复异常，如网络断开、心跳超时、单次重连失败、用户回调异常。

  • ERROR：SDK 不会因为正常业务失败主动输出 error，调用方可在捕获异常后自行决定。

18.4. 敏感字段

不要在应用日志中输出以下字段原始值：

  • Authorization

  • accessToken

  • refreshToken

  • wsToken

  • token

  • SecretKey / secretKey

  • sign

  • nonce

  • 完整敏感 URL query

SDK 自身日志会对上述精确字段名做脱敏，tokenExpireTime 这类非敏感字段不会因为包含 token 子串被误脱敏。

注意：Tyrus 框架自身在 FINE / FINER 等细粒度级别可能输出完整连接 URI。生产环境不要开启 Tyrus 的细粒度日志，避免框架层输出包含 wsToken 的原始 URI。

18.5. 机器人任务排查示例

一次机器人任务可能跨越 HTTP、WebSocket 和本地缓存。建议按同一个 traceId 串联排查：

event=send_command traceId=sdk-a1b2c3d4e5f6 robotId=R001 taskId=T001
event=http_success traceId=sdk-a1b2c3d4e5f6 method=POST path=/api/open/v1/robot/command/R001 requestId=...
event=task_cache_registered traceId=sdk-a1b2c3d4e5f6 taskId=T001 taskStatus=PENDING
event=task_cache_updated traceId=sdk-a1b2c3d4e5f6 taskId=T001 taskStatus=FINISHED payloadLength=128
event=get_task_result_batch traceId=sdk-a1b2c3d4e5f6 robotId=R001 batchNo=1 from=0 to=1

如果没有收到 WS TASK_REPLY，可用同一个 traceId 查看补偿查询 getTaskResult 的 HTTP requestId，再结合服务端日志定位。

19. 错误码

Open API 业务错误会映射为 ServiceException。常见类别：

  • 认证失败：AccessKey 不存在、签名错误、Token 过期。

  • 权限或状态错误：AccessKey 被禁用、机器人不可用、资源不存在。

  • 请求参数错误：必填字段缺失、指令参数格式不符合接口要求。

  • 限流：请求频率超过 Open API 限额。

完整错误码以交付给开发者的 Open API 错误码文档为准。

20. 对象速查

核心对象：

  • URobotClient：SDK 入口。

  • AccessKeyCredentials：AccessKey/SecretKey 凭证。

  • TokenManager：Token 获取、缓存和刷新。

  • HttpConfiguration：HTTP 超时、连接池和代理配置。

  • RetryPolicy：重试次数和退避策略。

  • PageRequest / PageResponse：分页基础模型。

服务对象按领域分布在 io.github.bwtrobot.opensdk.services.robot.model 和 io.github.bwtrobot.opensdk.services.map.model 包下。

21. 指令速查

sendCommand 使用 SendCommandRequest 下发机器人指令：

  • robotId：机器人 SN 或 Open API 约定的机器人标识。

  • type：指令类型。

  • messagesType：消息类型。

  • params：指令参数对象。

  • callbackUrl：任务回调地址，可为空。

params 是开放对象，SDK 不在客户端强行收紧结构。新增或调整指令时，以交付给开发者的 Open API 文档和业务指令定义为准。

22. 枚举速查

SDK 当前以字符串或整数承载 Open API 枚举值，避免新增枚举时旧版 SDK 反序列化失败。

常见枚举包括：

  • 机器人指令 type。

  • 机器人指令 messagesType。

  • 地图、路径、动作和讲解资源状态。

新增枚举值通常按 PATCH 版本同步文档；如需要强类型枚举，将在后续 MINOR 版本中补充兼容封装。

23.2. Topic 数据形态与消费方式

每次推送通过 TopicData 传递，同一条消息可同时承载 JSON 文本与二进制数据：

  • topic() — Topic 名称

  • jsonData() — JSON 文本（可能为 null），hasJson() 判断是否非空

  • binaryData() — 二进制数据（可能为 null），hasBinary() 判断是否非空

订阅示例（SDK）：

realtime.onTopic(Topics.CMD_VEL_ROBOT, data -> {
    if (data.hasJson()) {
        System.out.println("速度数据: " + data.jsonData());
    }
});

realtime.onTopic(Topics.CURRENT_POINTCLOUD, data -> {
    if (data.hasBinary()) {
        byte[] pointcloud = data.binaryData(); // 处理点云二进制
    }
});

同一 Topic 重复 onTopic() 时新回调替换旧回调；unsubscribe(topic) 取消订阅；重连后 SDK 自动重订阅所有已注册 Topic。

23.3. robot_upload_info 快照

robot_upload_info 是机器人状态聚合 Topic。订阅后 SDK 自动维护最新 JSON 快照，可随时通过 realtime.getRobotInfo() 获取（未收到时返回 null）。

23.4. 渲染类高频 Topic（点云 / 相机）

Note

本节描述的二进制转发、节流（throttleRate / fps）、帧格式、rosbridge 信封解析均为示例工程「浏览器实时桥」的应用层约定，非 SDK 协议。直接使用 SDK 时，TopicData 已提供原始 JSON 与二进制，是否降采样、如何解析由调用方自行决定。

点云与相机数据高频且体量大。示例工程将其归为「渲染类 Topic」，与普通摘要类 Topic 区别处理。其订阅目录（前端 realtimeTopicCatalog）：

23.4.1. 节流（降采样）

示例后端 RobotRealtimeService 按订阅时携带的 throttleRate（毫秒）做时间窗口节流：距上次转发不足 throttleRate 的二进制帧直接丢弃，避免压垮浏览器。fps = 1000 / throttleRate。

23.4.2. 浏览器二进制帧格式

示例后端转发给浏览器的二进制帧采用「Topic 头 + 载荷」结构，便于前端识别来源 Topic：

[ uint16 topicLength (大端) ][ topic UTF-8 字节 ][ 原始二进制载荷 ]

前端 decodeBinaryFrame() 据此切分出 topic 与 data。

23.4.3. rosbridge 信封

渲染类 Topic 若以 JSON 形式下发，外层是 rosbridge 风格信封，真正消息体在 msg 字段中，点云 / 图像的实际数据通常以 base64 放在 msg.data：

{ "topic": "/x_nav/current_pointcloud", "msg": { "data": "<base64...>", "...": "..." } }

23.5. 任务结果推送（task_reply）

OpenAPI 任务的实时状态通过任务结果通道推送，注册 onTaskResult 回调接收。SDK 内部会从推送 JSON 中解析 taskId、taskStatus 并更新 TaskCache。

示例前端在解析 task_reply 时对字段名做了兜底兼容：

  • 任务 ID：task_id / taskId / taskID

  • 任务状态：task_status / taskStatus / status

realtime.onTaskResult(data -> {
    System.out.println("任务结果: " + data.jsonData());
});

任务下发后通过 task_reply 实时跟踪状态流转，直至到达终态（如 completed / failed / canceled / timeout）。

23.6. 连接状态

示例工程将 SDK 连接事件归一化为以下状态供前端展示：

23.8. TaskCache 行为

  • sendCommand() 返回后自动注册 taskId（状态 PENDING），前提是 RobotRealtimeClient 已连接。

  • WS 推送 TASK_REPLY 时自动更新缓存（覆盖 jsonData 和 status）。

  • get(taskId) 返回缓存的 JSON 数据，未命中或已过期返回 null。

  • getStatus(taskId) 返回任务状态字符串。

  • TaskCache 缓存，由 task_reply 推送实时更新。

  • LRU 淘汰：条目数达到 taskCacheMaxSize 时淘汰最久未访问的条目。

  • TTL 过期：条目超过 taskCacheTtl 未被访问或更新时，get() 返回 null。

24. 兼容性和升级

SDK 使用语义化版本号：

  • PATCH：修复问题、完善文档或补充错误码说明。

  • MINOR：新增兼容能力，例如新增接口、可选参数或响应字段。

  • MAJOR：包含不兼容变更，例如方法签名调整、字段类型变化或接口移除。

升级 SDK 前建议先阅读随 SDK 交付的版本说明，重点关注以下内容：

  • 是否调整了最低 JDK 版本。

  • 是否新增或移除了依赖。

  • 是否有标记为废弃的接口需要迁移。

  • 是否存在 MAJOR 版本的不兼容变更。

默认情况下，SDK 的 JSON 反序列化会忽略未知字段。Open API 新增响应字段时，旧版 SDK 通常可以继续运行；应用只有在需要读取新字段或调用新接口时才需要升级 SDK。
