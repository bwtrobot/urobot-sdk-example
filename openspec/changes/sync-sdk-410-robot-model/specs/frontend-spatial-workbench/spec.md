## ADDED Requirements

### Requirement: 前端机型详情查询能力
前端 SHALL 提供以 modelCode 查询机型详情的 API 封装和完整类型，支持嵌套文件、历史可空字段和动态机型编码，并通过现有调试机制区分真实与演示数据。

#### Scenario: 查询参数编码
- **WHEN** 调用方传入包含空格、加号或中文的有效机型编码
- **THEN** 后端接收到与输入一致的 modelCode，不因 URL 拼接丢失字符

#### Scenario: 接收详情
- **WHEN** 后端成功返回机型详情
- **THEN** 调用方能够读取动态编码、嵌套文件及 null 历史字段，来源标记为 real

#### Scenario: 演示降级
- **WHEN** 机型查询失败且启用现有 mock 降级
- **THEN** 调试记录及返回来源明确标记 mock，结果不得作为真实集成成功依据

### Requirement: 前端保留机器人动态机型信息
前端 SHALL 保留列表中的动态机型字段，并允许历史机型字段为空。

#### Scenario: 接收动态编码
- **WHEN** 机器人列表包含新动态编码且历史枚举字段为空
- **THEN** 前端能够保留并传递该编码，不要求它属于固定枚举
