## ADDED Requirements

### Requirement: 前端机型详情查询能力
前端 SHALL 提供以 modelCode 查询机型详情的 API 封装和完整类型，支持嵌套文件、历史可空字段和动态机型编码，并通过现有调试机制区分真实与演示数据。

#### Scenario: 查询参数编码
- **WHEN** 调用方传入包含空格、加号或中文的有效机型编码
- **THEN** 后端接收到与输入一致的 modelCode，不因 URL 拼接丢失字符

#### Scenario: 接收详情
- **WHEN** 后端成功返回机型详情
- **THEN** 调用方能够读取动态编码、嵌套文件及 null 历史字段，来源标记为 real

#### Scenario: 演示降级
- **WHEN** 机型查询失败且启用现有 mock 降级
- **THEN** 调试记录及返回来源明确标记 mock，结果不得作为真实集成成功依据

### Requirement: 前端保留机器人动态机型信息
前端 SHALL 保留列表中的动态机型字段，并允许历史机型字段为空。

#### Scenario: 接收动态编码
- **WHEN** 机器人列表包含新动态编码且历史枚举字段为空
- **THEN** 前端能够保留并传递该编码，不要求它属于固定枚举


### Requirement: 按动态机型编码加载机器人三维模型
前端 SHALL 优先使用选中机器人的非空 model_code，兼容 modelCode，查询真实机型详情，并根据 urdf.url 和 urdfMainPath 加载三维模型。有效编码 MUST 原样传递，不依赖旧机型枚举。

#### Scenario: 加载动态机型
- **WHEN** 选中的机器人具有动态机型编码且查询返回真实 URDF 资源
- **THEN** 场景显示该资源对应的机器人模型，并应用最新运行时位姿及既有 ROS 到三维坐标转换

#### Scenario: 直接 URDF 与 ZIP
- **WHEN** 资源为直接 URDF 或包含 URDF 的 ZIP 包
- **THEN** 系统能够解析主文件及相对路径、package 引用的网格与贴图；ZIP 主路径缺省时只自动选择唯一 URDF，路径缺失或存在歧义时显示简易模型

#### Scenario: 动态资源不可用
- **WHEN** 查询失败、返回 mock、资源为空、下载或网格解析失败
- **THEN** 显示简易模型，不使用其他型号的本地模型伪装为该动态机型，并允许再次选择后重试

#### Scenario: 无编码旧数据
- **WHEN** 机器人没有可用的 model_code 或 modelCode
- **THEN** 保留现有本地机型模型选择行为，未知机型显示简易模型

### Requirement: 模型加载生命周期正确
前端 SHALL 复用同机型在途和已加载资源，提供局部加载反馈，并保证机器人切换、模型替换和视图销毁后的资源与状态正确。

#### Scenario: 同机型复用
- **WHEN** 连续选择相同机型或收到该机器人的更新信息
- **THEN** 不重复发起相同在途查询或下载，已有模型继续使用最新位姿

#### Scenario: 快速切换或销毁
- **WHEN** 旧模型尚未加载完成就切换机型或销毁视图
- **THEN** 旧响应不覆盖新场景、不复活已销毁视图，并释放迟到对象和资源

#### Scenario: 模型替换与加载反馈
- **WHEN** 模型正在加载或被替换
- **THEN** 视图提供局部加载状态且不冻结位姿更新；释放不再使用的几何体、材质、纹理及 Blob URL
